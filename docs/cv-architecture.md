# CV Architecture

There is no universal perfect CV layout.

The structure should make the candidate's strongest relevant evidence easy to find.

## General information order

A useful default:

1. Identity / target
2. Contact information
3. Short profile
4. Core relevant capabilities
5. Most relevant/current experience
6. Earlier experience compressed according to relevance
7. Technical / domain tools
8. Education / training / languages

## Information hierarchy

Prioritize:
- relevance
- evidence strength
- recency where meaningful
- impact
- credibility
- readability

Do not mechanically give every past job equal space.

## Career changers

Avoid framing such as:

> "trying to break into..."

Instead show the trajectory and transferable mechanics truthfully.

Older experience can be compressed into a foundational block when the recurring responsibilities matter more than the individual employer names.

## Visual principles

Prefer:
- one clear reading order
- strong typography
- restrained design
- selectable text
- consistent dates
- enough whitespace to scan quickly

Avoid:
- skill-rating bars
- icons replacing important words
- decorative complexity
- tiny type used only to force one page
- layouts that produce broken text extraction

## Page count

One page is useful when it remains readable.

Two clear pages are better than one compressed page.
